# Lilith Learning Lab

A standalone, offline Android app with a talking, animated Teacher. It comes **empty**: you import courses as JSON files, and it teaches them as animated lectures with concept maps, glossary, key points, quizzes, practice labs, a final exam and progress tracking.

* Every chapter: concept map (with an animated tour), summary, glossary, key points, lesson, then quiz and practice.
* Practice labs: fill, order, match, write, code (JavaScript, runs on the device), **python** (MicroPython 1.29 in WebAssembly, built in, runs on the device, ~0.7 MB), scripted terminal, and **webxdc** apps that can travel inside the course JSON.
* Final exam: a course can define `finalExam`; otherwise it is built from the chapter quizzes.
* Courses are stored on the device, can be deleted, and can be shared as JSON. Progress is kept per course.
* Offline by design: the only network use is the optional **Browse online** screen, which downloads courses from this repository (`courses/catalog.json`) and talks to raw.githubusercontent.com only. Voice uses the phone's own text-to-speech.
* Courses carry optional `category`, `level` and `tags`; the library groups and searches by them.

## AI features (optional, off until you set them up)

Settings > AI settings (or the Office tab) connects the app to **Ollama on your own computer**, **Ollama Cloud** (API key) or **any OpenAI-compatible endpoint**. Nothing is sent anywhere until you do.

* **Office hours**: talk to Teacher about the whole course (Office tab), after every lecture section (an "Ask Teacher" pause after the summary, glossary, key points, lesson and quiz; switch it off in AI settings), on every lab, and from the Read view or the header help button. Each chat knows the section or lab you are on (and your current answer) and keeps its history per chapter.
* **Tools**: Teacher searches the installed courses with BM25 (Okapi ranking, as in `rank_bm25`, with the Lucene idf), can use `web_search` and `web_fetch` (Ollama Cloud web API with a key, otherwise Wikipedia/DuckDuckGo search and the r.jina.ai reader), checks arithmetic in Python, and for a question that needs several sources runs **deep research** on its own in the background. You only see the answer and its sources.
* **Decisions API**: Ollama's `/v1/systemone` (local and cloud, model `clef` by default on cloud) grades **explanations** (the "Check my explanation" chip): type your explanation and get a score with a confidence, then feedback. Scanning lists chat models and decision models separately. If no decision model is set, the chat model gives the verdict.
* **Build with AI** (Library; you can also add your own documents (.txt .md .html .docx .pptx .pdf) and the course is built from them, with no web research): enter a topic, level and chapter count; you see one progress bar. In the background Teacher first does deep research on the whole topic, then an agent plans the chapters, writes each one (summary, glossary, key points, lesson, quiz, flashcards, concept map, fill/order/match labs and a ELI5 block), checks it against the course format, fixes what fails and assembles the course with a **Sources** chapter. If the model cannot work with tools, the builder switches to a fixed step-by-step method ("Quick", for small models). Verify the facts: AI-written courses can be wrong.
* **Hidden workspace**: the research and building happen in a private workspace from the [Jade Agent Kit](https://github.com/lucky-edgelord/Jade-agent-kit) (a virtual file system, a BusyBox shell, MicroPython, BM25 file search and a task list), bundled in the app (`kit.js`, loaded only when the AI needs it) so it works offline. The agent follows **skills** (deep-research, course-builder, lilith-course format, office-hours) and keeps notes and drafts in files; the learner never sees them.
* **A model for each job**: AI settings has optional *Course generation model* and *Office hours model* boxes (same provider, blank means the main model), so a large model can write courses while a fast one answers questions. Scan models fills the pick list for both.
* **Tables and references in every chapter**: a lesson block `{"type":"table","title":"...","head":["Term","Meaning"],"rows":[["a","b"]]}` and a chapter field `"references": [{"title","url","note"}]`. The AI course builder is told to write both and its `check_chapter` tool asks for them; if a model still leaves them out, the finished course gets a Key terms table from the glossary and references from the pages it read. The validator warns when a chapter has neither, the editor has a Table block and a References section, and `build/apply_tables.py` (run by `make_catalog.py`) gives every shipped course a Key terms table and a references list (`build/references/<course-id>.json` holds real links when known; otherwise a plain note that none were fetched).
* **Log**: AI settings > Log shows what the AI features did (scans, requests, tool calls, errors; API keys are hidden). Turn on *Verbose log* to record every request and tool call. Copy it when reporting a problem.
* **Settings file**: Settings > Settings file > Export / Import (also in AI settings) saves the app settings, course source and AI settings as `lilith-settings.json`; API keys are included only if you switch that on. Import checks every value and ignores anything it does not know.
* **Android**: requests go through the app's native HTTP bridge (streamed), because Ollama Cloud and most APIs do not allow web pages to call them (no CORS). Cleartext HTTP is allowed so a phone can reach Ollama on your LAN.
* **Web version**: a local Ollama must allow the site (`OLLAMA_ORIGINS="https://lucky-edgelord.github.io"` or `"*"`). Ollama Cloud needs a CORS proxy: deploy [`docs/proxy/cloudflare-worker.js`](docs/proxy/cloudflare-worker.js) (free Cloudflare Worker, limited to a few hosts and to this site) and set *CORS proxy* to `https://<worker>.workers.dev/?{url}`.
* Code: `build/src/ai.js` (providers, tools, BM25, decisions, skills, agent, research, builder, log, settings import/export), `build/src/net.js` (Android bridge, proxy, the kit's offline files), `build/vendor/jade-agent-kit/` and the UI in `build/src/app.html`.

## Course editor

**https://lucky-edgelord.github.io/Lilith-Learning-Lab/editor/** writes and edits courses by hand in the browser: course details, chapters (add, duplicate, reorder, delete), the ELI5 block, summary, key points, glossary, lesson blocks (text, code, math, figures, concept maps), quizzes, flashcards, concept maps, practice labs (forms for fill, order, match and Python; JSON for write, code, terminal and webxdc), the final exam, pronunciation and the raw JSON of a chapter or the whole course. It checks the course with the app's own validator as you type (problems are listed and marked per chapter), autosaves a draft in the browser, has undo, opens files, pasted JSON or any course from the library, downloads `<id>.course.json`, and **Try in the app** opens the course in the web app. In the app, Library > Make your own course > Course editor links to it. Rebuild with `python3 build/build_web.py --editor docs/editor`.

## Web version

The same app runs in any modern browser, with no install and no server: **https://lucky-edgelord.github.io/Lilith-Learning-Lab/app/** (once GitHub Pages is on: Settings > Pages > Branch `main`, folder `/docs`). It is plain HTML, CSS and JavaScript, uses the browser's own speech synthesis, runs Python labs on the same MicroPython WebAssembly build, keeps courses and progress in the browser, and is an installable offline PWA (manifest plus service worker). On wide screens the layout centres and shows the teacher beside the slides. Rebuild with `python3 build/build_web.py --pages docs/app`. It can also be hosted on any static file server; the folder is self-contained (about 3 MB).

## Lilith University (website) and the course catalog

* `courses/catalog.json` lists every course with its category, level, tags, counts and a chapter outline. Rebuild it with `python3 build/make_catalog.py` after adding a course (register new ids in `build/catalog_meta.json`: `{"id": ["Category", "Level", ["tag", ...]]}`).
* `docs/index.html` is **Lilith University**, a static page (GitHub Pages, source: `main` branch, `/docs` folder) where you can search courses, filter by category and read each course's outline before downloading it.
* In the app, **Library > Browse online** shows the same catalog; **Get** downloads and imports a course. The source repository can be changed in **Source**.

Simulation, not the real compiler. Examples are our own, inspired by The Rust Programming Language (MIT/Apache-2.0).
* `lilith-university.course.json`: a very short orientation in 4 chapters: what Lilith University is, finding and getting courses, how to study a chapter, and how to make and share your own course. Rebuild with `python3 build/make_lilith_university_course.py`.
* `emulator-programming.course.json`: how to write an emulator in 13 chapters, using a tiny 8-bit CPU: the fetch-decode-execute loop, decoding, flags and endianness, memory maps, cycle timing, interrupts and schedulers, video and sound, input and DMA, caches and JITs (with the 1990s advice brought up to date), accuracy and hardware-derived tests, and debuggers; 47 Python labs.
* `mathematics-for-cs-ai.course.json`: Mathematics for Computer Science and AI (17 chapters: logic and proof, sets and functions, counting, graphs, number theory, linear algebra I and II, calculus, multivariate calculus, optimization, probability, distributions, statistics, information theory, Markov chains, algebra and category theory, type theory and the lambda calculus). 122 labs, 71 of them Python labs on the built-in MicroPython, and a 38-question final exam.
* `data-structures-algorithms.course.json`: Data Structures and Algorithms (13 chapters: Big-O, arrays, linked lists, stacks and queues, hash tables, trees, heaps, graph traversal, sorting, binary search, recursion, dynamic programming, greedy algorithms with shortest paths and spanning trees). 96 labs, 57 of them Python labs on the built-in MicroPython, and a 34-question final exam.

Every chapter of every course opens with an ELI5 block ("explain it like I am five"): a very plain everyday analogy. The text lives in `build/eli5/<course-id>.py` and is inserted into the course JSON by `build/apply_eli5.py` (run automatically by `build/make_catalog.py`).
* `sample-percentages.course.json`: a tiny second-subject sample.

Course format: see the header of `build/src/course.js` or use "Template" and "AI prompt" in the app's library.

## Build

* `build/make_course.py <out.json>`, `build/make_rl_course.py <out.json>` and `build/make_sample.py <out.json>` regenerate the courses.
* `python3 build/build_web.py --web <dir>` writes the web app (`index.html` + `avatar/`).
* Tests (from `build/`; the Playwright ones use Chrome): `bash tests/run_all.sh` runs them all:
  `node tests/test_course.js` (course format and labs), `node tests/test_ai.js` (AI engine against mock servers: providers, tools, decisions, builder, settings import/export, log), `node tests/proxy_test.mjs` (the CORS proxy template),
  `python3 tests/workspace_test.py <web>` (the hidden workspace over http and file://, and the Android bridge with a fake native side), `python3 tests/ai_ui_test.py <web> ../courses [shots]` (office hours, background research, the agent builder and its fallback, settings files, the log),
  `python3 tests/ui_test.py <web> ../courses [shots]`, `python3 tests/store_test.py <web> ../courses` and `python3 tests/editor_test.py ../courses [shots]` (the course editor, including a lossless round trip of every course).
* `android/build_apk.sh` builds and signs the APK with the plain Android SDK tools (no Gradle). It creates a local keystore on first run; do not commit it.

## Jade

`jade/tools/lilith_tool.js` (search, read, quiz, validate courses) and `jade/skills/lilith-learning-lab/SKILL.md`. `xavier_tool.js` adds a trtexec builder, DLA checker and simulated shell for the Xavier course.

Avatar art is the non-explicit frame set only. The APK is untested on a physical device from the build environment.


## Math (LaTeX)

Lesson text, quiz options, glossary entries and labs accept LaTeX: `$x^2$` inline, `$$...$$` or `\[...\]` displayed, `\(...\)` inline, `\$` for a literal dollar sign. A lesson block `{"type":"math","tex":"..."}` is a displayed formula. KaTeX 0.19.1 (MIT) is bundled and runs offline. The Teacher's voice reads formulas as words and captions show a plain unicode form. In JSON, double every backslash.
